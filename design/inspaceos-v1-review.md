# InSpaceOS 初版设计审核稿

> 状态：仅设计原型，未接入正式业务代码
> 依据：`InSpaceOS 创始人寄语.docx`、`SpaceOS 白皮书 V2.0.docx`

## 一、设计判断

InSpaceOS 初版不是旅游攻略 SaaS，也不是另一个地图工具。它要证明的是：

> **导航结束后，现实地点仍然有一个可以进入、记忆和交流的数字空间。**

因此初版不把 3D、AI、去中心化、商业广告等长期愿景放在首屏，而是先让用户理解并完成一件事：

```text
看见一个真实地点 → 进入它的空间 → 看到这里发生过/正在发生的事
```

## 二、用户路径

### 普通访客

1. 首页理解“为什么需要 InSpaceOS”。
2. 进入空间地图，按地点找空间。
3. 进入某个空间，查看地点故事、当前状态和在场交流。
4. 通过链接或二维码分享给同行者。

### 空间主理人

1. 从导航进入“创建空间”。
2. 绑定一个真实地点。
3. 添加空间介绍、记忆、现场信息或私密访问规则。
4. 在“我的空间”维护内容。

## 三、导航结构

```text
InSpaceOS
├── 空间地图       普通访客的主入口
├── 空间记忆       浏览地点留下的故事与内容
├── 创建空间       主理人入口
├── 我的空间       已登录用户管理入口
└── 关于 InSpaceOS  创始人寄语 / 白皮书
```

## 四、首页结构

### 1. 首屏

**标题：**

> 导航结束后，体验才开始。

**说明：**

> InSpaceOS 为现实中的地点建立数字空间。来到一间咖啡馆、一条街或一个地标后，你可以看见这里留下的故事、正在发生的事情，以及同样身处这里的人。

**主行动：** `进入空间地图`

**次行动：** `了解 InSpaceOS`

右侧不是装饰性 3D 概念图，而是一个“地点空间”的小样本：

- 地点名称
- 一条历史记忆
- 当前在场人数
- 进入空间按钮

### 2. 三句话解释产品

- **地图带你到达。**
- **空间让地点留下记忆。**
- **在场的人可以继续交流。**

### 3. 一个真实例子

以“外滩”或“某家咖啡馆”为例，展示：

- 这里曾经发生过什么
- 现在有什么人在这里
- 为什么用户值得进入这个空间

### 4. 主理人入口

不要在首屏和游客抢注意力，放在页面下方：

> 你比别人更了解这个地方？为它建立一个空间。

## 五、空间详情结构

```text
地点名称 + 城市
├── 现在这里       当前时间、天气/状态、在场人数
├── 这里的记忆     图片、文字、历史片段、漂流瓶
├── 进入交流       在场聊天 / 私密空间验证
├── 空间说明       主理人介绍与地点信息
└── 分享空间       链接 / 二维码
```

## 六、视觉方向

- 背景：带少量天空蓝倾向的雾白，保持开放与通透。
- 主色：天空蓝，用于主按钮、导航高亮和可交互状态，表达探索、开放与连接。
- 深色：深海蓝，用于标题、顶部区域和沉浸式空间画面，表达深度、记忆与未知。
- 状态色：橙色只保留给少量坐标警示、密码状态或需要用户立即注意的提示，不再作为品牌主色。
- 所有正式页面通过语义化设计 Token 使用颜色，避免页面单独写死色值。
- 图形：地图线、坐标、时间标记、记忆片段，不使用泛化的 SaaS 渐变。
- 字体：大标题短而有停顿，正文保持 16px 以上、行长适中。
- 动效：只用于地图点位、状态变化和页面切换；支持 reduced-motion。

## 七、明确不做

- 首页不展示大量未实现的 3D/AI/协议能力。
- 不把“Space / Guide / QR”作为用户必须先理解的术语。
- 不用四个以上并列 CTA。
- 不把白皮书的宏大叙事直接复制成产品营销文案。
- 不把游客和主理人入口混在同一层级。

## 八、审核点

请优先审核：

1. **主标题是否符合 InSpaceOS，而不是普通旅游产品。**
2. **“空间地图 → 空间详情”的主路径是否清楚。**
3. **空间详情是否体现“记忆 + 在场 + 交流”，而不是只展示攻略。**
4. **视觉是否足够克制，是否还有模板化 SaaS 感。**
5. **初版是否应该先保留“空间记忆”还是先保留“攻略”。**

## 九、后台可编辑首页标题

首页主标题不写死在组件中，由后台“站点设置”管理。

### 后台字段

- 首页主标题（中文）
- 首页主标题（英文）
- 首页说明（中文）
- 首页说明（英文）
- 是否启用自定义文案
- 最后修改人 / 最后修改时间

### 初始默认值

- 中文：`导航结束后，体验才开始。`
- 英文：`When navigation ends, the experience begins.`

### 技术规则

1. 公开首页只读取已发布的站点设置。
2. 没有配置、读取失败或字段为空时，自动使用代码中的默认文案。
3. 只有管理员可以修改和发布。
4. 保存前提供首页预览，发布时记录审计日志。
5. 中文与英文分别维护，切换语言时不会临时机器翻译。
6. 初版只开放标题和说明，避免后台变成复杂 CMS。

## 十、修正版核心闭环：攻略与在线互助

初版空间的核心不是单独的“记忆”，而是三层协作：

```text
Space（真实地点容器）
├── Guide（经过整理的共同知识）
├── Room（围绕地点与攻略发生的在线互助）
└── Memory（长期沉淀的地点故事与时间内容）
```

### Guide / 空间攻略

攻略负责建立讨论的共同上下文，包括：

- 到达路线与交通
- 玩法和时间安排
- 吃喝与周边服务
- 现场规则和避坑
- 主理人整理的高频问题

### Room / 在线空间

在线空间不是没有主题的群聊。讨论必须围绕地点、攻略和此刻发生的问题：

- 攻略没有写清楚的地方可以继续提问。
- 在场用户可以补充天气、人流、营业和路线变化。
- 熟悉地点的人可以远程回答。
- 有价值的回答由主理人整理回攻略，形成知识循环。

### Memory / 空间记忆

记忆仍然保留，但在初版中是空间的长期内容层，不抢占“攻略 + 在线互助”的主闭环。

## 十一、整页后台编辑器

后台不是只编辑标题，而是管理完整首页。建议使用结构化页面配置 JSON，而不是允许管理员直接输入任意 HTML 或 JavaScript。

### 可编辑内容

- 页面模块的显示、隐藏与顺序
- 每个模块的中英文标题、正文和提示语
- 按钮文字、链接、主次层级
- 图片、视频封面或空间示例
- 首页 SEO 标题与描述
- 导航显示名称

### 可编辑风格

- 天空蓝 / 深海蓝主题预设
- 主色、深色、背景色和状态色
- 标题字号档位
- 内容宽度与页面密度
- 圆角与阴影等级
- 首屏图文布局
- 模块背景样式

### 安全边界

- 不允许后台插入任意 JavaScript。
- 自定义样式存为经过校验的设计 Token 和模块配置。
- 图片上传经过类型与大小校验。
- 草稿、预览和正式发布分离。
- 每次发布生成版本，可查看差异并一键回滚。
- 发布操作记录管理员和时间。


## 本轮补充：攻略运营与移动端入口

### 空间攻略管理

正式后台应保留原站已经存在的业务能力，并重新组织为清晰的内容运营工作台：

- 按标题、地点和所属空间搜索
- 按草稿、已发布、已归档筛选
- 新建、编辑、预览、发布、取消发布、归档和恢复
- 显示攻略与真实 Space 的绑定关系
- 显示空间讨论中“待整理为攻略”的有效回答
- 形成“讨论 → 标记 → 整理 → 审核 → 发布”的沉淀工作流

### 移动端主菜单

手机端采用固定底部菜单，首版保留四个高频入口：

1. 首页
2. 空间地图
3. 空间攻略
4. 我的空间（创建与管理入口放在内部）

菜单项同时使用图标和文字，触摸区域不小于 44px，并为页面底部预留安全区，避免遮挡正文。
