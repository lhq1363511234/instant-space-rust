# Instant Space Rust Phase 计划

> 依据：`docs/ARCHITECTURE_RUST.md`  
> 目标：先稳定“地图 + 登录 + 创建 + 我的空间”的闭环，再逐步补齐主理人管理、攻略、实时互动和后台运营。

---


## 产品基线：全球旅行攻略空间

从 2026-07-09 起，后续 Phase 统一围绕 `docs/PRODUCT_VISION.md` 执行：

```text
Instant Space = 全球旅行攻略与共享体验空间平台
Space = 真实旅行地点的数字入口，也是地图默认显示对象
Guide = Space 下的结构化攻略内容，也可作为独立攻略存在
Community = 当前用 Discord/QQ 承接，后续升级站内实时互动
QR/Link = 空间的线下扫码和分享增长入口
```

关键关系：

```text
Space 1 : N Guide
Guide.space_id optional
```

因此，后续开发必须满足：

- 首页第一屏必须先讲清楚产品价值，不能只显示地图；建议主文案：**发现全球旅行攻略空间，扫码进入真实地点的共享体验。**
- 首屏 UX 必须包含：强价值文案、搜索主行动、浏览攻略/创建空间次行动、快速场景入口，并在移动端避免多浮层叠加。
- 首屏必须有图片化视觉和轻量动效：地图点位、扫码手机、二维码、攻略卡片、共享体验提示；不能只有地图、文字和按钮。
- 地图默认显示空间，不默认显示攻略。
- 空间详情页必须展示相关攻略。
- 管理空间时必须能查看、新建、编辑、删除/归档相关攻略。
- 写攻略时必须能选择绑定已有空间，或创建不绑定空间的独立攻略。
- 普通用户只能编辑自己的空间和攻略；admin/super_admin 可管理全部。
- 已保存攻略再次保存必须更新同一条 guide，不能因为保存多次生成重复攻略。

## 0. 当前差距判断

对照架构文档，当前项目不是方向错，而是很多能力还停留在“可演示基础版”。下一步不应该继续零散加功能，而要按闭环推进。

### 0.1 已经基本完成

- `/inspace` 首页地图探索。
- MapLibre 本地资源和 `/inspace/ofm` 同源代理。
- 页面切换回首页地图重挂载。
- 中英切换基础能力。
- 统一登录 / 注册。
- 登录后头像入口。
- 创建空间弹窗。
- 弹窗地图选点填写经纬度。
- `/inspace/my-spaces` 基础页面。
- `/inspace/admin` 基础后台入口。
- 私密空间密码版本的领域边界。
- 攻略层级筛选基础能力。

### 0.2 目前最需要改的地方

#### P0：用户闭环不完整

1. 登录后 Header 依赖 `current_session`，但登录成功后全局 session 刷新机制还不够明确。
2. 没有退出登录。
3. 创建空间成功后，首页地图和“我的空间”列表不会自动刷新。
4. Header 当前路由高亮仍偏粗糙，容易一直显示 Explore。
5. 创建空间表单字段太少：缺少空间类型、自定义类型、描述、标签、有效期。

#### P0：我的空间只是列表，不是管理

1. 不能编辑空间信息。
2. 不能关闭 / 重新激活空间。
3. 不能更换空间密码。
4. 不能申请驻留。
5. 不能归档为空间模板。

#### P1：私密空间访问还没形成完整产品体验

1. 访问验证需要更明确地落到 `access_sessions`。
2. 私密空间进入后的页面/聊天权限还不完整。
3. 密码轮换后旧访问不会立刻踢出；但发送消息必须重新校验当前密码版本。

#### P1：攻略系统仍是浏览基础版

1. 没有攻略详情页。
2. 没有结构化攻略编辑器。
3. 用户投稿、个人草稿和后台内容管理流程还不完整。
4. 攻略和空间的关联展示还不完整。

#### P1：后台运营能力不足

1. Admin 只有基础入口和统计。
2. 缺空间管理、攻略管理、驻留审批、用户管理。
3. 缺统一操作结果和错误展示。

#### P2：实时互动未开始

1. 聊天还没有 WebSocket 通道。
2. 求助和游戏还没有产品化页面。
3. 在线人数还不是实时数据。

#### P2：生产工程化还需要补齐

1. 数据导入需要完整迁移旧 SQLite 的空间和攻略。
2. 缺定期任务处理空间过期。
3. 缺统一错误格式、日志追踪和备份脚本。
4. 当前未提交改动较多，需要分阶段整理提交，避免不可追踪。

## Phase 1：稳定用户主闭环

### 目标

让普通用户完成完整流程：注册/登录 → 看到头像 → 创建空间 → 地图出现新空间 → 我的空间可见 → 可退出。

### 范围

#### 1. 会话与 Header

- 增加 `logout_user` server function。
- Header 头像菜单包含：我的空间、退出登录。
- 登录 / 注册成功后触发全局 session 刷新或跳转到首页。
- Header 根据当前路径高亮：Explore / Guides / My Spaces。

#### 2. 创建空间弹窗

- 创建成功后：
  - 显示成功状态。
  - 可一键关闭弹窗。
  - 首页地图刷新空间点。
  - 我的空间列表刷新。
- 表单补字段：
  - 空间类型：景点 / 美食 / 公园 / 交通 / 活动 / 自定义。
  - 自定义类型名称。
  - 中文描述、英文描述。
  - 标签。
  - 有效期：默认 24 小时。
- 经纬度字段继续保留，但地图选点是主要交互。

#### 3. 我的空间基础管理

- 我的空间卡片展示：状态、公开性、有效期、坐标、在线数。
- 空间详情抽屉或管理弹窗。
- 先实现只读详情，为 Phase 2 编辑做准备。

### 验收标准

- 未登录点击创建空间，提示登录。
- 登录后 Header 显示头像和用户入口。
- 点击退出后 Header 回到 Sign in。
- 创建空间后，不刷新页面也能在首页地图看到新 marker。
- `/inspace/my-spaces` 能看到刚创建的空间。
- 移动端弹窗不横向溢出。

### 必须测试

```bash
npm run test:browser
npm run test:map-runtime
DATABASE_URL=postgres://instant_space:instant_space_pass@127.0.0.1:5432/instant_space_rust cargo test --workspace
```

## Phase 2：主理人空间管理

### 目标

让主理人能管理自己的空间生命周期和私密访问。

### 范围

#### 1. DB / repository

- 增加更新空间基础信息 repository。
- 增加空间生命周期操作 repository：
  - close
  - reactivate
  - regenerate_password
  - archive_template
  - apply_resident
- 密码轮换必须 `password_version + 1`。

#### 2. Server Functions

- `update_my_space`
- `close_my_space`
- `reactivate_my_space`
- `regenerate_space_password`
- `archive_my_space_template`
- `apply_space_resident`

权限规则：

```text
current_user.id == spaces.host_user_id OR current_user.role is admin
```

#### 3. UI

- 我的空间详情编辑表单。
- 关闭 / 重开按钮。
- 更换密码按钮，并显示新的 WiFi 热点名格式。
- 申请驻留按钮。
- 归档模板入口。

### 验收标准

- 用户只能修改自己的空间。
- 非 owner 请求被拒绝。
- 密码轮换后旧 access session 仍可保持页面读取；发送消息时必须提示重新输入密码。
- 关闭空间后首页不再作为 active 空间展示，或按产品规则显示为 closed。
- 重新激活后回到地图。

### 必须测试

- Rust repository 单元/集成测试。
- Browser：我的空间编辑和生命周期按钮。
- 私密访问版本失效测试。

### Phase 2 当前实现状态（2026-07-05）

已完成主理人最小管理闭环：

- 我的空间卡片展开管理面板。
- 编辑基础信息：名称、位置、坐标、公开性。
- 关闭空间 / 重新激活。
- 重置空间密码，并显示新 6 位密码和 `InstantSpace_XXXXXX` 热点名。
- 申请驻留。
- 归档为空间模板状态。
- 服务端校验 owner 或 admin 权限。
- 密码重置时 `password_version + 1`，旧访问会话不立刻踢出；发送消息时若版本不匹配会提示重新输入密码。

仍留到后续优化：

- 更完整的空间详情页。
- 编辑描述、标签、自定义类型、有效期的二次管理。
- 操作确认弹窗和审计日志。
- Admin 端统一审批和管理界面。

- 管理弹窗增加空间密码说明：
  - 旧密码已加密保存，不能反查显示。
  - 主理人可点击“重置并显示新密码”生成新密码。
  - 新密码和 `InstantSpace_XXXXXX` 热点名只展示一次。
- 浏览器测试覆盖：管理弹窗打开、地图选点、重置密码、空间生命周期操作。

### Phase 2.4 删除空间与移动端设备识别（2026-07-05）

继续补齐主理人和安卓移动端体验：

- 我的空间管理弹窗新增“删除空间”。
- 删除采用软删除：空间状态置为 `archived`，不再出现在首页和“我的空间”列表，后续后台仍可做审计/恢复能力。

  - 地图控制和底部空间抽屉减少遮挡。
  - 创建/管理弹窗在手机上接近全屏，避免内容塞满并横向溢出。

## Phase 3：私密空间与聊天入口

### 目标

把“私密空间需要密码”从展示功能升级成完整访问系统，并为实时聊天打基础。

### 范围

- `verify_space_password` 写入 `access_sessions`。
- 私密空间详情中显示进入空间入口。
- 进入私密空间前检查 access session。
- Chat 页面或抽屉先做非 WebSocket 的持久化消息列表。
- 发消息时校验 password version。

### 验收标准

- 未验证不能进入私密聊天。
- 验证后可进入。
- 空间密码轮换后旧验证不能发消息。
- 刷新页面后短期内仍保留访问权限。

### Phase 3 当前实现状态（2026-07-05）

已完成私密空间和聊天入口的非实时闭环：

- `verify_space_password` 会写入 `access_sessions`，并下发 12 小时 HttpOnly 访问 cookie。
- 私密空间验证成功后显示“进入私密聊天”入口。
- 新增 `/inspace/spaces/:space_id` 空间聊天页。
- 进入聊天页前会检查：
  - 公共空间可直接进入。
  - 私密空间必须有有效 access session。
  - access session 存在且未过期即可继续查看页面，避免主理人改密后把已在空间内的人立刻踢出。
- 新增持久化聊天消息：
  - 列表读取数据库 `chat_messages`。
  - 发送消息写入数据库。
  - 发消息时再次校验私密访问和当前密码版本；版本不一致提示重新输入密码。
- 浏览器刷新后，12 小时内仍可进入已验证私密空间。
- 增加测试覆盖：
  - 私密空间验证 → 进入聊天 → 发送消息 → 刷新仍可访问。
  - 密码轮换后旧 access session 仍可查看页面，但不能继续发送消息。

后续 Phase 6 再把当前持久化聊天升级为 WebSocket 实时聊天、在线人数和断线重连。

### Phase 3.1 社群密码分发与空间详情提示（2026-07-05）

## Phase 4：攻略系统升级

### 目标

让攻略成为可浏览、可编辑、可关联空间的正式内容系统。

### 范围

- 攻略详情页。
- 结构化 sections 展示。
- 用户创建攻略草稿。
- 后台内容管理：管理员可管理、发布、归档攻略，但不作为逐条人工审核员。
- 攻略关联空间。
- 图片 URL 管理，后续再考虑上传。

### 验收标准

- 省 → 市 → 区 → 景点筛选稳定。
- 攻略详情 URL 可分享。
- 用户投稿默认 draft。
- 管理后台可发布 / 归档 / 管理攻略。

### Phase 4.1 攻略详情页与分享 URL（2026-07-06）

后续 Phase 4.2 继续做结构化攻略编辑器和草稿投稿。

### Phase 4.2 结构化攻略编辑器草稿版（2026-07-06）

已完成结构化编辑器的结构化对象版闭环：

- 新增投稿入口：
  - `/guides/new`
  - `/inspace/guides/new`
- 攻略列表页增加“提交攻略 / Submit guide”入口。
- 未登录用户访问编辑器会提示登录。
- 登录用户可以打开结构化攻略编辑器。
- 顶层用一个 `GuideDraft` signal 持有整篇攻略对象，不再把每个字段拆成独立 signal。
- 组件拆分为：
  - `GuideEditor`：基本信息、摘要、板块列表、封面图片、底部保存按钮。
  - `SectionEditor`：受控编辑单个结构化板块。
  - `ImageManager`：受控管理 URL 图片数组，使用 `Url::parse()` 校验并展示预览网格。
- 编辑器支持 Guide 字段：
  - 中英文标题。
  - 中英文摘要。
  - guideType、category。
  - 省 / 州、城市、区县、地点。
  - images 图片 URL 数组（第一张作为封面）。
  - sections 结构化板块数组。
  - status：draft / published / archived。
  - featured：仅 admin mode 显示入口。
- Section 字段使用新结构：
  - `id`
  - `type`
  - `title_zh/title_en`
  - `content_zh/content_en`
  - `images`
- 后端 `guides.sections` 和 `guides.images` 继续使用 jsonb，写入时序列化 Rust struct，读取时兼容旧 seed 的 `heading/body` 格式。
- `create_guide_draft` server function 支持保存草稿、保存并发布、取消发布（archived）。

### Phase 4.3 空间与攻略关系修正（当前优先级）

目标：解决“我有多个空间时，写攻略到底对应哪个空间；如果不想绑定空间怎么办”的产品逻辑问题。

范围：

- 攻略编辑器增加明确的空间绑定选择：
  - 绑定已有空间。
  - 不绑定空间，作为独立攻略。
- 从某个 Space 详情或管理入口点击“写攻略”时，自动带入当前 `space_id`。
- Space 详情页展示该空间下的攻略。
- 管理 Space 弹窗/页面增加“相关攻略”模块：
  - 写新攻略。
  - 查看已绑定攻略。
  - 编辑攻略。
  - 删除/归档攻略。
- 管理端或 super_admin 视角能看到并管理所有空间和攻略。
- 普通用户只能编辑/删除自己创建的攻略，不能编辑别人创建的空间或攻略。
- 保存已存在攻略必须更新同一条记录，不能重复生成多份攻略。

验收标准：

- 用户管理一个空间时，可以直接看到该空间关联的攻略。
- 用户从该空间写攻略，保存后攻略自动绑定该空间。
- 用户从攻略页新建时，可以选择任一可用空间，也可以选择独立攻略。
- 普通用户看不到别人内容的编辑/删除入口；直接调用服务端也会被拒绝。
- admin/super_admin 可以管理全部空间和攻略。
